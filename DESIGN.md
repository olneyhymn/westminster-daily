# Design language

The site and the email are one design: a printed devotional page. Georgia on
parchment, gold rules, burgundy accents, no photography, no boxes that look like
software. The reading is the product; everything else recedes.

`static/scss/custom.scss` implements the site and
`templates/newsletter-buttondown.html` implements the email. This file is the
intent. When they disagree, the code is wrong.

## Colour

Six roles, each with one job and a contrast floor.

| role | hex | job | floor |
|---|---|---|---|
| ink | `#2C1810` | body copy | 16.6:1 on cream |
| accent | `#5C1A2A` | headings, links, the current date | 12.6:1 on cream |
| ink-muted | `#6B5D45` | **all** secondary text, at any size | 4.5:1, always |
| ornament | `#C4A265` | rules, separators, flourishes | none (never carries text) |
| edge | `#D6CBAF` | borders | none |
| surface | `#FFFDF7` page, `#E8E0D2` recessed | backgrounds | exempt |

**Say quiet with size, not value.** The palette fails when de-emphasis raises
the value until the text stops being readable. Six elements failed AA that way,
including one brown that missed by 0.09. Use size, weight, letter-spacing, and
position instead. A 10px tracked uppercase label in a dark brown reads quiet and
stays legible.

**Ornament never carries meaning.** Gold is 2.37:1, correct for a rule and wrong
for anything a reader has to parse.

**No new tints.** A surface at 1.05:1 against its background is a border. Use
cream or parchment. If two zones need separating and neither value fits, use a
rule.

**Warm only.** Every colour sits between 27° and 45° except the accent at 345°.
A cool grey, even one that passes AA, reads as pasted in from another website.

## Type

Georgia everywhere, on both surfaces. Body 16px/1.78.

| | size | style |
|---|---|---|
| h1 | 27px | roman |
| h2 | 22px | italic |
| h3 | 18px | italic |
| h4 | 16px | italic |
| h5, h6 | 15px | roman |

Bulma's minireset sets every heading to `font-size: 100%`, so the scale above is
load-bearing: delete it and every heading becomes body text with no build error.

Utility labels (masthead, audio, section markers) are 10–13px, uppercase,
letter-spaced 1–3px, in ink-muted. Use that treatment for furniture, never for
reading.

## Links

- In running prose: underlined. Accent burgundy is also heading burgundy, so a
  link without an underline reads as emphasis.
- In navigation rows: no underline. Position already says "link."
- Index rows whose entire text is the link (`li > a:only-child`): no underline.
  107 underlined rows is a thicket.

## Email

Everything above applies, plus:

- Tables and inline styles only. No stylesheet, no class hooks, no web fonts.
- Minimum 13px for anything clickable, with padding to a ~24px tap target. 10px
  letter-spaced type is legible on desktop and illegible on a phone.
- `templates/newsletter-buttondown.html` is the source of truth.
  `worker/src/template.html` is a gitignored copy regenerated by
  `npm run sync-template`. Never edit the copy.
- The email prints proof texts in full; the web page keeps them in popovers.
  That divergence is deliberate. Keep the day counter and the reading identical.

## Checks before shipping

1. `make all`, then look at four views: a daily reading, Start Here, a catechism
   index, and the footer of any page. Hard-reload; the browser caches
   `main.css`.
2. Confirm the heading scale survived. An h1 that matches its body text means
   the scale is gone.
3. Check contrast for any colour you touched. Nothing that carries words goes
   under 4.5:1, whatever its size.
4. For email changes, render a real reading with its proof texts and send
   yourself a test. Long footnotes are where email layouts break.
